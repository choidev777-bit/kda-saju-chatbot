# Project Agent Rules

This project uses a lightweight ratchet harness for AI-assisted development.

- If the request is ambiguous, clarify before changing files.
- Keep changes scoped to the current task.
- Do not add dependencies without explicit approval.
- Do not delete, skip, or weaken tests to make work appear complete.
- Before claiming completion, run the strongest available verification and report any gap.
- Treat failed verification, repeated mistakes, unsafe shortcuts, and user corrections as ratchet signals.
- For new product or feature work, run the planning workflow before implementation: office-hours, then superpowers:brainstorming, then superpowers:writing-plans.
- Use the `harness-workflow` skill when starting a new project, new feature, idea review, or harness workflow.
- Keep `HARNESS_PLAN.md` updated with Current Phase, Active Spec, and Active Implementation Plan.
